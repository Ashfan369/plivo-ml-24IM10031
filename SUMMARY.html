End-of-Turn Detection — Solution Summary

Task: for every silence pause in a user turn, output p_eot, the probability the turn is over, using only audio strictly before pause_start. Metric: mean response delay at ≤5% interrupted turns.

Why the silence-only baseline fails — and why it beats the status quo differently per language

Hindi mid-turn hesitations are short (90th percentile ≈ 0.63 s), so a fixed 850 ms silence timer is already near-optimal there — the win must come from firing faster than 850 ms on true ends. English hesitations routinely last 1–3 s, so any timer short enough to be responsive interrupts users; the agent is forced to the 1.6 s timeout. A classifier that reads the speech leading into the pause breaks this tradeoff: it can pair a low action delay with a threshold that stays quiet on hesitations.

The model

57 features9-model gradient-boosting blendduration-weighted holdsjoint EN+HI training

  1. Prosody of the final ≈1.5 s — energy decay into the pause (final 50/100/300 ms vs peak, slopes over 200/500 ms), speaker-median-normalized final F0 level / slope / fall (statements fall; continuations stay level or rise), final voiced-run length (final-syllable lengthening) and normalized run length, unvoiced tail duration, pitch range, near-silence fraction.
  2. Segmental snapshot — 12 mean-normalized log-mel bands over the last 300 ms plus their delta vs the previous 300 ms: a crude, ASR-free "what sound did they end on" cue that separates trailing fillers ("uh…", nasals) from crisp clause-final stops. This was the single biggest Hindi improvement (850 → 720 ms in isolation).
  3. Turn context — elapsed time, number of pauses already taken, speech-burst length since the previous pause, previous pause duration, speaker pitch register. All strictly in the past.
Key metric-driven idea: a hold pause can only cause a false cutoff if the user stays silent longer than the agent's action delay. So holds are weighted in training by 0.2 + 4·min(dur, 1.6) — the classifier spends its capacity suppressing exactly the dangerous long hesitations and is allowed to be sloppy on 200 ms micro-pauses the delay already covers. Duration is used only as a training weight, never as a feature (it is future information at inference).

The final predictor is the average of 9 models (3 seeds × {GBM depth-4, GBM depth-2, HistGradientBoosting}). Single configurations flip-flopped between languages on 496 pauses; the blend is the robust choice for a hidden, mostly-Hindi test set. Joint EN+HI training beat per-language models on both languages.

Causality

Every feature is computed from audio[0 : pause_start·sr] of the current pause. The per-turn context features use only pauses whose pause_end precedes the current pause_start (i.e., pauses already resumed — fully in the past). The current pause's pause_end/duration is never touched at inference; it appears only as a training-time sample weight.

Where it still fails

  • Long "thinking" hesitations that end on a prosodically complete clause — falling pitch, clean stop, then the user adds a constraint 2 s later. Indistinguishable without lexical/semantic context.
  • Pauses within the first second of a turn (pitch statistics undefined).
  • English generally (AUC 0.63): its holds are prosodically well-formed sentence ends far more often than Hindi's.
